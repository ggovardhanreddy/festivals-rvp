# Internationalisation

**Status:** implemented in Phase 1A. English at `/`, Telugu at `/te/`.

## URL model

| Language | Prefix | Example |
|---|---|---|
| English (default) | none | `/about/` |
| Telugu | `/te` | `/te/about/` |

English keeps the bare path, so **every existing URL is untouched and zero
redirects were needed**. `lib/i18n/config.ts` is the only module that knows
this; `localeFromPath`, `stripLocale` and `withLocale` are the helpers.

`/terms/` and `/temples/` are correctly *not* Telugu — the prefix check matches
the `te` segment, not the prefix of a word. Asserted in `tests/unit/i18n.test.ts`.

## Catalogue

- `lib/i18n/messages/en.ts` — the reference. Every key must exist here.
- `lib/i18n/messages/te.ts` — `Partial`, so a missing key is legal.
- `lib/i18n/index.ts` — `translate(locale, key, fallback?, values?)`

**Fallback chain:** requested locale → English → caller's fallback → the key.
A missing Telugu string renders readable English. It never renders a key name
and never a machine translation.

Legacy `t("/about/")` href-keys used by the header and footer still work via
an alias table, so nothing had to be migrated at once.

Coverage today: **202 English keys, 130 Telugu (64%)**. `npm run i18n:check`
prints this and fails only when code uses a key missing from English.

## Locale is URL-driven

`LanguageProvider` derives the locale from `usePathname()`. `localStorage`
(`rvp-ui-lang`) records a preference for the switcher only — it never overrides
the path, because two visitors on the same URL must see the same page.

## Switcher

`components/i18n/LanguageSwitcher.tsx` maps the current page to its counterpart.
When no translation exists it links to the locale root and says so. **It never
links to a URL that would 404.** Asserted in `tests/e2e/i18n.spec.ts`.

## hreflang

Emitted only where a translation genuinely exists, driven by `hasTelugu` in
`lib/routes/registry.ts`. Today that is `/` alone. Advertising a Telugu
alternate for an untranslated page tells Google something untrue.

## Typography

Self-hosted, no network at build:

| Face | Weights | Bytes |
|---|---|---|
| Playfair Display (latin) | 600, 700 | 46 KB |
| Poppins (latin) | 400, 600 | 16 KB |
| Noto Sans Telugu | 400, 600 | 75 KB |

Neither Playfair nor Poppins contains a single Telugu glyph, so before this
Telugu fell back to whatever the device had. `:lang(te)` applies the Telugu
stack and a taller `--leading-telugu`, so any Telugu string picks up correct
rendering without a per-component override — including the bilingual
panchangam labels on English pages.

`npm run fonts:sync` refreshes the files from the Fontsource devDependencies.

## Adding a translation

1. Add the key to `en.ts`.
2. Add the Telugu to `te.ts` (optional; English shows until you do).
3. Use `t("your.key")`.
4. To publish a page at `/te/...`, create the route **and** set `hasTelugu: true`
   in the registry. Setting the flag without the page breaks the switcher, and
   the route test will catch it.
